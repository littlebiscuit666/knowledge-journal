今天学到一份「网站开发任务」级别的提示词：不是让 AI 画个页面，而是把它当成产品设计师 + UI/UX + 全栈工程师，按阶段交付一个每日历史解谜网站（Chronicle / 历史谜局）。原文完整归档如下：

```text
# Chronicle — 历史谜局网站开发任务

你是一名资深产品设计师、UI/UX 设计师和全栈开发工程师。请设计并实现一个具有国际化互联网产品水准的每日历史解谜网站。

## 1. 产品定位
项目名称：Chronicle / 历史谜局（暂定）
品牌文案：Every day hides a story. / 每一天，都藏着一段历史。
产品结合：
- Kaggle 的专业平台感与导航体系。
- Wikipedia 的历史知识和每日更新机制。
- Wordle 的轻量每日挑战体验。
- Criterion Collection 的艺术电影海报审美。
不要复制上述网站的具体界面，而是提取它们的优秀设计理念。
核心理念：网站是现代的，内容是历史的，奖励是艺术的。

## 2. Skills 使用要求
开发前读取并使用以下已安装 Skills：frontend-design、ui-ux-pro-max、next-best-practices、vercel-react-best-practices、web-design-guidelines。
如果 Skill 不存在，先说明缺失情况，不要假装已经使用。
首先生成 DESIGN.md，统一颜色、字体、间距、边框、布局、交互和动画规范，然后再开发。

## 3. 核心玩法
每天发布一个与当天日期有关的真实历史事件。每道题包含三个逐步揭晓的提示（悬念→特征→事实），默认只展示第一层；玩家可随时提交答案，也可主动解锁下一层；答错保留进度，允许主动揭晓答案。
禁止使用虚假在线人数、虚假排名或虚假紧迫感。

## 4. 页面设计
每日挑战页 / 揭晓结果页 / 历史档案页 / 海报收藏页 / 排行榜 / 个人主页，共六类页面，各自有明确的必含元素与禁止事项（如：未猜中前不能泄露答案；档案页未完成与已完成事件要有视觉区别避免剧透）。

## 5. 海报系统
竖版 2:3，风格随历史事件变化（胶片纪实/艺术电影/铜版画/古典油画/复古未来主义）。正面极简：标题、右上角日期、一句核实过的名言、右下角玩家签名、一幅有明确视觉中心的图。背面：介绍、破解顺序、提示用量、完成日期、唯一收藏编号、来源与再现说明、品牌标识。每天只生成一张公共背景图，个人签名由程序动态渲染。

## 6. 视觉设计规范
Editorial Design + Swiss Modernism。主色 #173757、强调色 #254D79、古典金 #B19B75、背景 #F7F8FA、正文 #172B40。Inter + 思源黑体 + 思源宋体 + 手写签名体。图标用 Lucide。
禁止：紫色渐变、玻璃拟态、满屏巨大圆角卡片、过度装饰按钮、泛滥阴影、Emoji 当正式图标、SaaS 营销式首页、无关占位内容。

## 7. 响应式设计
桌面端左侧导航 + 明确网格；手机端单列 + 底部导航（今日/档案/收藏/我的），排行榜走顶部入口；测试宽度覆盖 375/390/768/1280/1440px；不得横向滚动。

## 8. 国际化
完整支持简中/英文切换（next-intl），所有文案集中管理；谜题、提示、介绍、可接受答案全部双语言；切换语言不得重置游戏进度；注意英文更长导致的布局变化。

## 9. 技术选型
Next.js App Router + TypeScript + Tailwind + shadcn/ui（不套默认视觉）+ next-intl + Lucide。正式版：PostgreSQL/Supabase + 对象存储 + Vercel。验证、提示解锁、破解顺序、排名全部服务端处理；首次正确答案用数据库事务分配唯一顺序；Asia/Shanghai 统一时区发布。

## 10. 开发流程
五阶段：①DESIGN.md+原型 ②核心玩法闭环 ③真实后端 ④海报生成与分享 ⑤Playwright 测试+设计审查。每阶段必须汇报：已完成功能、测试结果、尚未实现的功能。第一阶段不引入支付/广告/社区/微服务。

## 11. 验收标准
成熟产品视觉水准、中英文完整可用、双端经过设计、完整猜谜与海报解锁流程、按钮不允许空壳交互、演示数据明确标注、海报有独立收藏价值、用户不会感觉自己正在参加考试。

请先完成设计系统和高质量的首页原型。不要急于实现全部后端业务。
```

## 值得学的写法

- **三重角色开场**：产品设计师 + UI/UX + 全栈，一次设定 AI 的能力范围和交付责任
- **参照系只借理念不抄界面**：「Kaggle 的专业感、Criterion 的海报审美……不要复制界面」，比形容词堆砌精准得多
- **反幻觉条款**：「如果 Skill 不存在，先说明缺失情况，不要假装已经使用」——专治 AI 假装读过文档
- **禁止清单比要求清单更有力**：紫色渐变/玻璃拟态/Emoji 图标逐个点名，比一句「要克制」管用十倍
- **数据诚信写进提示词**：禁止虚假在线人数、排名必须服务端真实生成——把产品伦理前置到规格层
- **强制分阶段汇报**：每阶段必须说「完成了什么、测了什么、还差什么」，压缩 AI 谎报进度的空间
- **验收标准量化**：按钮不允许空壳、演示数据要标注、覆盖 5 档屏幕宽度——「完成」有了客观定义
- **收尾一句防跑偏**：「先完成设计系统和首页原型，不要急于实现全部后端」——防止 AI 一上来铺十个子系统
