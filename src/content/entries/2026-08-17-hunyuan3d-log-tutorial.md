> 日期：2026-08-17 ｜ 配套部署：`2026-08-17_Hunyuan3D-2本地XPU部署完成.md`
> 用途：看懂 infer.py / 网页每次出模打印的每一行日志，理解三个可调参数各自管什么

## 〇、整条流水线总览

```
输入图片 ──rembg抠图──► 透明底图 ──DINOv2提特征──► 图像条件
                                                        │
随机噪声(3072个shape token) ──DiT去噪×30步◄─────────────┘
        │
        ▼
隐向量 ──VAE解码──► 256³密度场(1670万体素) ──Marching Cubes──► 三角网格 ──► GLB
```

四段耗时大致比例（本地 130T 实测 131~200s/模）：**采样 ~40% + 抽面后处理 ~55% + 其他 ~5%**

## 一、日志逐行解读（以实测杯子为例）

```
[img] C:\...\tmpxxx.png: no alpha, running rembg ...
Diffusion Sampling:: 100%|███| 30/30 [00:52<00:00, 1.75s/it]
Volume Decoding: 100%|███| 2122/2122 [00:03<00:00, 641.94it/s]
vertices=437466 faces=874936
extents x/y/z = 1.993/1.990/1.421 (thin ratio 0.71)
watertight=False
saved: D:\Hunyuan3D\outputs\web_xxx.glb (131.4s)
peak XPU mem: 4.14 GB
```

### 1. `[img] ... no alpha, running rembg ...` —— 抠图
- 传的是普通照片（无透明通道）→ 用 **u2net**（ONNX 分割模型，本地 `~/.u2net\u2net.onnx`，2026-07-16 就装好了）把主体抠出、背景变透明
- 传 RGBA 透明底图则显示 `has alpha, skip rembg` 直接跳过
- **为什么必须抠**：3D 生成的第一原则是模型只该"看见"物体本身——背景一旦混进去，会被当成几何体一起建出来（多出一坨底座/背景板）

### 2. `Diffusion Sampling: 30/30 [00:52, 1.75s/it]` —— 扩散去噪（主角）
- 1.1B 参数的 **DiT**（Diffusion Transformer）在干活
- 从一团随机噪声 shape token 出发，每步：DINOv2 提取的图像特征"指挥"方向，DiT 预测并减掉一点噪声；30 步后噪声被"雕刻"成明确形状
- **1.75s/步 × 30 = 52s**，整条流水线唯一跑满核显的重活

### 3. `Volume Decoding: 2122/2122` —— 隐向量 → 密度场
- VAE 解码器把 3072 个压缩 token 还原成 **256³ ≈ 1670 万体素的密度场**（每体素一个值：此处实心 or 空）
- 分 2122 块批处理，仅 3 秒，不是瓶颈

### 4. `vertices=437466 faces=874936` —— 抽面
- **Marching Cubes**：在密度场里找实心/空心的交界面，抽成三角网格
- 闭合网格面数 ≈ 2×顶点数，所以数字总是成对出现
- 这个杯子 43.7 万顶点（对照：官方 demo 才 15.5 万）——**形状越复杂，这段越慢**，这就是同参数下 131s 和 200s 差异的来源

### 5. `extents x/y/z = 1.99/1.99/1.42 (thin ratio 0.71)` —— 质量体检
- 三轴包围盒边长；**thin ratio = 最短轴/最长轴**
- 0.71 = 三围匀称、饱满立体 ✔
- **<0.1 是警报**：被压成纸片了 → 换 45° 视角的图重跑（正面平拍/图标/logo 没有透视线索，模型只能猜深度，猜出来就是薄片）

### 6. `watertight=False` —— 不是 bug
- marching cubes 的**非流形夹点**（一条边被 3+ 面共享）：网格本身完全封闭、无开口边（boundary edges=0）
- CUDA 同参数同样会出；看模/进 Blender 零影响，只有 3D 打印在乎，且切片软件能自动修复

### 7. `saved: ... (131.4s)` + `peak XPU mem: 4.14 GB`
- 全程 ≈ 抠图 2s + 采样 52s + 解码 3s + 抽面后处理 ~74s
- 峰值显存 4.14G / 16G，核显余量充足（推理期间系统卡顿是核显算力被占满、桌面渲染同卡抢资源，出完即恢复）

## 二、三个旋钮各管哪一段

| 参数 | 作用阶段 | 效果 | 建议 |
|---|---|---|---|
| **steps**（步数，默认30） | 只影响采样段 | 多=细节略多，线性变慢；20~50 视觉差别不大 | 日常 20~30；**要提速先砍这里**（30→20 省 17s） |
| **guidance**（引导强度，默认5） | 采样方向 | 低=模型自由发挥（更圆润）；高=死板贴图、过高会畸形 | **5 就是甜点**，一般不用动 |
| **octree**（分辨率，默认256） | 解码+抽面段 | 196/256/384 → 网格密度与顶点数差数倍，**耗时差别最大的一档**；384 顶点暴涨、后处理显著变慢 | 屏幕上看模 196~256 足够；要进 Blender 精修再上 384 |

一句话：**steps 管慢工出细活，guidance 管听话程度，octree 管网格精细度**。

## 三、快速排障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| thin ratio < 0.1 | 输入图正面平拍/无透视 | 换 45° 视角图 |
| 出模多一坨"底座" | 背景没抠干净 | 换透明底图，或清理输入图背景 |
| `[warn] rembg unavailable` | u2net.onnx 缺失 | 下载放 `~/.u2net\u2net.onnx`（现已就位） |
| `Cannot find empty port: 7860` | 上一个服务没退 | Ctrl+C 旧的，或加 `--port 7861` |
| 系统卡成幻灯片 | 核显被推理占满 | 正常，出完恢复；期间别剪视频 |
