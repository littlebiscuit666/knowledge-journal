## 三、数据工程（自研流水线）

### 3.1 数据来源与清洗

原始语料：chinese-poetry 数据集（全唐诗 57,591 首，繁体 JSON，含题目/作者/正文/平仄）。

清洗规则：

1. 按 `author == 李白` 过滤 → 1,206 首
2. 去除正文中的校勘注：`（一作……）`、`〔…〕` 等异文标注（36 首受污染）
3. 内容去重（24 组重复）+ 残句剔除（<10 字）
4. **OpenCC 繁转简**（用户提示词为简体，训练-推理语言一致）
5. 最终可用 **1,181 首**

### 3.2 自动特征提取

- **体式检测**：按标点拆句后统计言数与句数 → 五言古诗 469 / 五言律诗 246 / 杂言 217 / 七绝 97 / 五绝 88……（分布符合李白"多古风、少律诗"的创作实际）
- **主题检测**：关键词加权分类 → 山水游历 / 游仙访道 / 饮酒 / 月亮 / 怀古咏史等 11 类

### 3.3 指令增广（解决小语料过拟合）

同一首诗配多种指令模板，让模型学"响应风格"而非"背诵原文"：

| 类型 | 示例 | 占比策略 |
|---|---|---|
| 命题式 | 请以《将进酒》为题写一首诗 | v1: 100% → **v2: 25%**（背诵捷径，刻意压低） |
| 主题式 | 写一首关于月亮的诗 | 主力（~85%） |
| 体式式 | 写一首五言绝句 | ~60% |
| 风格式 | 模仿李白豪放飘逸的风格写一首诗 | ~50% |
| 首句式 | 以"明月出天山"为首句续写成诗 | ~25% |
| 续写式（v2 新增） | 给前两联，补全后文 | ~15%（逼模型学结构而非整首检索） |

### 3.4 输出格式

LLaMA-Factory / trl 兼容的 alpaca 格式，**train/val 按整首诗切分**（防止同诗跨集泄漏）：

```json
{"instruction": "我想读一首写饮酒的诗，请你创作",
 "input": "",
 "output": "玉树春归日，金宫乐事多。……"}
```

## 四、训练方案

LoRA 只训练低秩适配器，冻结基座：

| 参数 | 配置 |
|---|---|
| target_modules | q/k/v/o_proj + gate/up/down_proj（全部注意力层+MLP） |
| r / alpha | 32 / 64（v1）→ **16 / 32（v2，削弱拟合容量）** |
| loss | **completion-only**（只在诗正文上计算损失，不学提示词） |
| 精度 | bf16 + gradient checkpointing（32G 显存占用 ~20G） |
| epochs / lr | 3 / 1e-4（v1）→ **2 / 5e-5（v2）** |
| 规模 | 621 步 / 27.8 分钟（v1）；346 步 / ~15 分钟（v2） |

## 五、评估、问题诊断与迭代（项目亮点）

### 5.1 v1 结果与问题

训练指标看似漂亮：train_loss 0.835 → **0.066**，eval_loss 稳定在 0.50。

但**生成测试暴露本质问题——模型变成了"背诗机"**：

| 测试指令 | v1 实际输出 |
|---|---|
| 写一首月下独饮的诗 | 逐字复述李白《月下独酌·其三》原诗 |
| 高铁远行（李白没写过的题材） | 无视主题，背诵《闻王昌龄左迁龙标》 |
| 台风夜 + 明确要求原创 | 原诗句拼贴，甚至出现乱码 token |

### 5.2 根因分析

- **数据格式制造了背诵捷径**：每条样本 output 含原题目（`《闻王昌龄…》\n原文`），模型学到"指令 → 检索最相关题名 → 复述原文"的捷径，而非风格映射；
- **拟合容量过剩**：3 epochs + lr 1e-4 + r=32 对 1,181 首短诗足以全部背下（train_loss 0.066 即证据），而基座本身预训练阶段就"见过"这些诗，LoRA 放大了复述倾向。

### 5.3 v2 改进措施

| 层面 | 措施 | 原理 |
|---|---|---|
| 数据 | **output 去除题目** | 斩断"题名→原文"检索链路 |
| 数据 | 命题式指令 100% → 25% | 指令不含原题，无法按题索骥 |
| 数据 | 新增续写式样本 | 训练结构/气脉理解而非整首记忆 |
| 训练 | epochs 3→2，lr 1e-4→5e-5，r 32→16，dropout 0.1 | 系统性削弱记忆容量 |
| 推理 | temperature/top_p 调参 + n-gram 重复检测（规划） | 抑制确定性复述 |

v2 训练 loss 下降明显更慢（第 20 步 0.73 vs v1 的 0.65），符合"无法靠背诵取巧"的预期。

### 5.4 评估工具

自建 Gradio 对比平台（端口 6006）：同一提示词、同一随机种子下，**原版 / v1 / v2 三模型并排生成**；基于 PEFT `load_adapter` + `set_adapter` 多适配器热切换，单卡共享一份 14G 基座权重。

## 八、可深挖的面试点

1. **为什么用 LoRA 而非全参微调？** —— 7B 全参需 ~60GB 显存（Adam 状态），单卡 32G 不可行；LoRA 只训 ~0.3% 参数，显存 20G，且适配器可热插拔、多版本共存。
2. **completion-only loss 的意义** —— 避免模型浪费容量学习"模仿提问"，梯度全部用于诗正文生成。
3. **小语料风格微调的核心矛盾** —— 语料太少（~1k 首）必然与过拟合/背诵搏斗；解法是数据侧消除捷径 + 训练侧限制容量 + 推理侧增加随机性三管齐下。
4. **评估不能只看 loss** —— train/eval loss 都"正常"，但生成测试证明模型不可用；建立了生成测试 + 三版对比平台的定性评估流程。
5. **train/val 切分粒度** —— 按"诗"而非"样本"切分，避免同一首诗的不同指令变体跨集造成泄漏。
